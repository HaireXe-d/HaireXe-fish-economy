# 消息路径：每次投消息前，把「已经说过的那段」收起来

> 一句话：**你的鱼每次收到消息，都附带着同一段流程说明；插件在它看见之前，把重复的部分收起来，只留第一份。**
> 装上就有，不用配置，不影响聊天。

---

## 一、以前是什么样

养鱼插件（QQ / B 站）每次把消息投进会话，不是只发"主人说：晚上吃什么"这一句，
而是捆着一整段固定说明：

```
【QQ 私信】主人（123456）刚给你发私信：

晚上吃什么？

————————————————
⚠️ 怎么让你的话送到主人 QQ：
   你在这里说的话，QQ 那边看不见，必须把回话写进这个文件：
      ~/.dsh/whale-work/dm-reply-qq.txt
   写完插件会自己发过去，然后把文件清空。
   行首写 [语音] 发语音；写 [表情] 发表情包。
————————————————
```

一条消息里，真正属于"这次对话"的可能就十几个字，剩下全是这段说明。

它有两个后果：

1. **模型每次都要重读一遍**；
2. 更麻烦的是——**它进了记忆**，之后每一轮请求都要再带一次。

实测你跑过的 11 个养鱼会话、1254 条入站消息：

| 项 | 数值 |
|---|---|
| 入站消息总字符 | 0.84M |
| 其中「之前发过的段落」 | **0.57M（67.5%）** |
| 这些重复段落被后续请求重复带上的总量 | 0.19B 字符 |

## 二、现在它怎么改

插件在养鱼插件投递的**那一瞬间**接一下，把消息里已经出现过的段落压成一句：

```
第二次收到：
【QQ 私信】主人（123456）刚给你发私信：

晚上吃什么？

按以下专属通道流程做：1) 这是主人 → 直接回……（后面 1288 字与上文相同，未变，不用重读）
```

- **第一份原样保留**，所以模型永远至少见过一次全文；
- 被压的那段不是删掉，而是换成「后面 N 字同上」，模型知道它没变；
- 正文（主人说的话）、图片、文件路径**一个字都不动**。

## 三、会不会影响聊天

不会。有四条保护：

| 保护 | 说明 |
|---|---|
| 只动重复段 | 第一次出现的段落、正文、图片、文件路径，全部原样 |
| 短段不压 | 少于 80 字（`messages.minChars`）的段落直接跳过 |
| 不划算不压 | 压缩后如果没省下 20 字以上，就当没这回事 |
| 出错必退 | 任何异常都按**原样**投递，绝不丢消息 |

另外它只在 `gate.scope` 匹配的会话里生效（默认 `whale`），你写代码的会话一条都不动。

## 四、能省多少

| 口径 | 数字 |
|---|---|
| 每条消息里被压掉的字符 | 约 65%（重复段留 35%） |
| 复利到全部请求 | **约 40M token（2.2%）** |

2.2% 听着不多，但它是**纯赚**：不动工具、不动压缩、不动人设，只是把重复的话换成一句"同上"。
而且消息短了，模型读得更快，回话会更利索一点。

## 五、是不是装上就能用

是。`messages.enabled` 默认 `true`，装完重启一次 DSH 就开始工作，不用改任何配置。

想调（一般不用）：

```yaml
config:
  messages:
    mode: short    # short 保留开头 / full 只留一句「同上」 / off 关掉
    minChars: 80   # 多长的段才处理
    keep: 200      # short 模式保留开头多少字
```

## 六、怎么确认它在工作

- `~/.dsh/fish-economy/summary.json` 里 `messageCharsSaved` / `messageCompressions` 会往上涨；
- 设置 → 养鱼经济学 卡片底部那行「消息省 X 字符」；
- 或者直接看鱼的回话：如果它开始抱怨「上面那段说过了」，说明压过头了——把 `mode` 改回 `short`、
  或把 `minChars` 调大。
