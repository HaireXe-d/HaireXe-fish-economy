# 合并说明：三个插件是怎么揉成一个的

> 三个来源：`dsh-flash-presets`（LarryE135）、`dsh-ops`（T-Auto）、以及本机一直在跑的"养鱼"插件。
> 原则：**只借思路，不搬代码；只做减法，不接管别人的东西。**

## 1. 对照表

| 来源 | 它最值钱的东西 | 我们怎么用 | 我们为什么不用它原来的做法 |
|---|---|---|---|
| dsh-flash-presets | ① 预设按场景收紧 ② 关掉用不上的工具省固定 schema | 分组 + 闸门 + `fish.enabled` 预设 | 它用"整卡替换系统提示"，会覆盖用户 persona，且两张卡同 id 会冲突；我们只在装配结果上做无损瘦身 |
| dsh-ops | ① 一个门面工具顶一组能力 ② 输出紧凑、批量、错误即数据 | `ops`（纯 Node，只读优先） | 它是 Rust worker + 原生 shell 载荷，许可证与分发成本高（Niubash 里带 GPL 组件），且它的工具名会隐藏官方工具；我们用可逆的 restrict |
| 养鱼插件（本机） | 场景：长人设 + 高频短对话 + 几乎不用工具 | `fish.enabled` 预设 | 不改它的任何一行代码；它继续说自己的人设，我们只管工具面与上下文入口 |

## 2. 逐项：从 flash-presets 搬了什么

| 它的做法 | 我们的对应物 | 差异 |
|---|---|---|
| 两个预设（lean-v3 / balance），13 条 / 3 条规则 | 「养鱼模式」预设（`fish.enabled`） | 我们不加规则，只改开关：工具归零、裁剪收紧、提示词去重 |
| 禁用 6 个用不上的插件（codex/claude-code 子代理、workflow、ralph、plugin-manager） | `gate` 把 `delegate`/`workflow`/`skill` 等组默认休眠 | 它改 profile 结构（不可逆、影响所有会话）；我们按会话 restrict（可逆、可随时唤醒） |
| compaction 阈值 0.25 / retain 20000 | `extras/compaction-aggressive.yml` | 我们不改它的数值，另给一个可选 overlay |
| tool-result-pruner 8192/4096/1024 | `trim.pruneToolResultChars = 3000` | 它在**事后**裁历史，我们在**入口**裁结果 |
| 整卡 persona 替换 | ❌ 不采用 | 会覆盖用户自己的 `deployment:persona-prefix`，且与别的预设互斥 |
| `ptc-runtime` profile 级覆盖 | ❌ 不采用 | 用户关不掉，且与合并方互相覆盖 |

## 3. 逐项：从 dsh-ops 搬了什么

| 它的做法 | 我们的对应物 | 差异 |
|---|---|---|
| 20 个 `ops_*` 工具，默认只发布 5 个常驻 | `ops` 一个工具 + `tool_list` 目录 | 我们不做"下一步激活"，直接分组休眠 |
| 紧凑输出（`=== FILE: … ===` + `N \| text`） | `renderBatch` 的 `## header` + 编号行 | 结构同理，格式重写 |
| 批量（read_files 1–32、edit_file 1–100） | `calls` 数组，串行、失败不影响其它 | 我们没做内并发 |
| 硬预算（64KiB / 128KiB / 2MiB） | `ops.maxChars`（默认 20K 字符）+ 中间省略 | 我们按字符不按字节 |
| 读去重（同内容替换为引用） | ❌ 不做 | 实测本机重复率只有 **0.3%**，见 `docs/效果实测.md` §7 |
| Rust worker / 原生索引 | ❌ 不做 | 分发与许可证成本高；纯 Node 够用 |
| 隐藏官方工具（`hideOfficialTools`） | 闸门 restrict | 我们可逆、可唤醒 |

## 4. 逐项：从养鱼插件搬了什么

| 它的做法 | 我们的对应物 | 说明 |
|---|---|---|
| 每次唤醒都重发人设 + 规则 | `agent/pre-step` 折叠同批重复长文本 | 只折叠**逐字重复**的块，不改写内容 |
| 高频短对话、几乎不用工具 | `fish.enabled`：工具面归零 | 聊天轮次的 schema 成本直接降到 4 个 meta 工具 |
| 会话很长 | 入口裁剪 + `extras` 里的 compaction overlay | 长会话才是省钱主战场 |

**没有动它的任何文件**：不 patch、不 fork、不改配置；它照旧运行，我们只在 DSH 层做减法。

| 项目 | 许可 | 我们是否复制了代码 |
|---|---|---|
| dsh-flash-presets | MIT | **没有**，只借思路与概念 |

并明确"没有复制代码"。如果以后要合并上游源码，按各自的 NOTICE 追加归属与变更声明。

## 6. 为什么是"三层减法"而不是"一个大补丁"

- **越靠近宿主机制的改动，越容易和别的插件打架。** restrict 只影响一个 agent；assemble waterfall 只改装配结果；
  post-execute 只改一条结果。三处都不碰"别人的注册"。
- **可逆。** 卸载插件 = 所有 restrict 自动失效、所有钩子注销；不用回滚任何配置。
- **可关。** 三个杠杆各有开关，出问题能单独关掉。

这也是合并里最贵的一课：**能借机制就别借代码，能加钩子就别改别人的行。**

## 7. 数据补一句

flash-presets 的作者自己在文档里写了「逐轮 token 没有精确统计，省多少目前是结构性推理」；
dsh-ops 没给端到端 token 数字。本仓库的 [效果实测](效果实测.md) 是拿**真实会话**算的，
口径和假设都写在文里，欢迎拿同样的脚本在你自己的 `~/.dsh/sessions` 上对一遍。
